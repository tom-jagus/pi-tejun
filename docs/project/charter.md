# Pi Tejun

## Problem

Recurring agent tasks require repeated instructions, manual coordination, and
attention to when work should run and where results belong. Ad hoc prompts and
commands make this work difficult to repeat, automate, and extend consistently.

## Value

A personal collection of repeatable workflows using the Pi harness should
reduce manual effort through automation and a consistent terminal interface.
The user can request work directly or have it run on approved schedules and
events, with results available for review at the desk.

## Success

- Named workflows can be invoked from the terminal without navigating to their
  implementation directories or reconstructing their instructions.
- Approved workflows can run automatically on defined schedules or events,
  within agreed limits and without continuous or off-hours supervision.
- Each run saves its results in a dedicated, known output location, with
  success, incomplete work, and failure clearly distinguishable.
- New workflows can be added within the project's boundaries through dedicated
  briefs, without changing the charter to enumerate them.
- Workflow definitions and shared execution support remain separate from the
  domain material, history, and user decisions they operate on.

## Boundaries

Pi Tejun owns reusable workflow definitions, workflow-specific instructions,
shared setup, consistent invocation, and automated execution using Pi. Manual
and automated execution serve the same workflow purpose and respect its agreed
inputs, outputs, and authority; not every workflow must use every trigger type.

Dedicated briefs define individual workflow outcomes, context, and constraints.
Workflow-specific destinations belong there rather than in a fixed catalogue
in this charter. Results and domain decisions stay in their dedicated locations
without making Pi Tejun a duplicate archive or source of project state.

General agent working standards and personal-memory management remain outside
this project's scope. Automation does not implicitly authorize source or policy
changes, project acceptance, Git mutations, or external publication. Instructions
alone are not technical access controls. Messaging integration is excluded for
now; results should not create an expectation of mobile supervision.

The project does not prescribe a scheduler, plugin, execution host, or command
syntax. Those choices need to support the agreed outcomes rather than define
which workflows the collection can contain.
